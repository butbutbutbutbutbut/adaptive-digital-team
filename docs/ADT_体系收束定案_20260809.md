# ADT 体系收束定案

> 日期：2026-08-09（晚）
> 状态：之 + 小禾（红队）对抗后定稿，待入 ADT 治理 repo

## 一、一句话定案

**ADT = 之lab 治理体系本身。** 不是底座，不是子系统，是整个组织的形状。

## 二、血统

ADT 前身是一套重型治理系统，内核两条基因保留至今：

- **可追溯**：证据留痕、收据、fingerprint，每一步有据可查
- **连坐**：Holder → Maker → Checker → 验收，整条链共同担责，非单点背锅

轻量化之后骨架不变——ADT 从来不是聊天玩具，是一套成熟治理系统的投影。

## 三、机构映射（封建王朝 → agent 治理）

| 王朝机构 | 职责 | ADT 对应 |
|---|---|---|
| 中书省 | 出令、定方向 | 安鼎（主Holder） |
| 门下省 | 封驳、审实质 | 红队（三视角对抗审查） |
| 尚书省 | 执行 | Maker / 各执行 agent |
| 六部 | 业务线 | workshop线、ADT线、个人网站线、飞书数据线、记忆体系…… |
| 都察院 | 审程序合规 | Checker（流程挑刺） |
| 锦衣卫 | 独立监察、直属皇帝、审体系本身 | 禾知止（反审查同伴） |

核心原则：**分权制衡 + 独立监察 + 可追溯连坐**。古法新用——agent 治理最缺的正是这套成熟骨架。

## 四、三条钉子（红队对抗后补）

### 钉子1 · 皇帝封驳：拍板可以坚持，但必须朱批留痕

- 关键决策（定案级/架构级/立项级）自动触发红队三视角审查
- 红队可正式**驳回**——驳回不是阻止，是"必须回应"
- 皇帝（之）有最终决定权，但须在决策记录中写明：
  **"已知红队驳回意见，仍坚持 X，理由：___"**
- 事后若 X 翻车，红队反对记录即免责证据——连坐保护体系，不绑架皇帝

### 钉子2 · 真否决首秀（实战案例 #001）

红队入制即生效，无需另找演练。

### 钉子3 · Checker 与红队边界

- **Checker（都察院）= 审程序**：规矩走没走、证据齐不齐、格式对不对
- **红队（门下省）= 审实质**：口径诚不诚实、数据真不真、决策站不站得住
- 触发点：Checker 在流程内跑；红队在**提交验收 / 拍板**节点开火

## 五、红队方法论（三视角）

每场红队审查跑三条独立只读线，互不串供：

1. **Human Facing** — 之的感知层：人看到的是不是真的、有没有误导
2. **事实严谨** — 逐条核对数据/证据，应迁/实迁/缺失全链路比对
3. **范式优雅** — 对照母本结构，架构是否站得住

产出：独立报告 + 汇总结论 + 修复/否决清单。封驳权见钉子1。
