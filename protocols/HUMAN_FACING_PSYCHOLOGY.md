## 1. 问题陈述

ADT 的本质产出不是文档和 PR，而是"推动用户（之）不断反思已有成果并推进任务"这件事本身。
Human Facing 接触面（Dispatch Card、Holder Summary、Human gate、收工汇报）的功能不能停留在
"状态报告"——告诉用户系统做了什么、产物在哪里。

状态报告模式下，用户面对接触面信息时的典型反应有两种：

- **机械验收**：字段齐全就点 ACCEPT，不审视成果本身是否值得推进、回退或调整；
- **机械推进**：把"任务完成"当作"该派下一个任务"的信号，没有在节点上停下来反思
  "已有成果是否支撑下一步"。

这两种反应都会让 Human gate 退化成流程开关，而不是决策节点。PT 轨道（ROADMAP.md § PT）
把每次 Human 验收定义为**黄金标签**——如果用户在机械验收，训练数据的质量就从根上坏了。

本协议引入认知心理学机制，目的不是让用户"更愿意点 ACCEPT"，而是让用户在关键节点
**真正看见自己的进度、承诺与未完成项**，从而做出有反思的决策。接触面的升级方向：

```text
状态报告（机械验收/机械推进） → 认知推动（反思已有成果 → 决定下一步）
```

## 2. 心理机制清单

| # | 机制 | 原理（一句话） | 在 ADT 中的落地形式 | 使用场景 | 轻量版直接可用 |
|---|---|---|---|---|---|
| 1 | 进度效应（Progress effect） | 已完成的部分可见时，人更愿意继续推进 | 收据/摘要展示已完成链：从 BASE 到 HEAD 的已验收任务链、阶段完成度与剩余差距 | Dispatch Card、Holder Summary | ✅ |
| 2 | 承诺一致性（Commitment consistency） | 人一旦公开承诺，会倾向于兑现 | Human gate 前的明确决策声明：重申用户此前确认的方向、验收标准与承诺基线，让本次决策与之对照 | Human gate、Dispatch Card | ✅ |
| 3 | 蔡格尼克效应（Zeigarnik effect） | 未完成的事持续占据注意力，驱动人推进 | 待办/缺口显式化：未关闭的开放项、被 REJECT 项、未验收候选以显式列表呈现，不淹没在完成列表里 | Holder Summary、收工汇报/跨机接力 | ✅ |
| 4 | 损失厌恶（Loss aversion） | 人倾向于避免已投入被浪费 | 展示已合并成果的"不可回退价值"：已 merge 的候选、已被接受的成果作为沉淀资产呈现，让停滞/回退的真实代价可见 | Holder Summary、收工汇报 | ✅ |
| 5 | 选择架构（Choice architecture） | 默认选项影响决策 | Human gate 的默认动作设计：默认动作是"查看证据/继续反思"，不是"直接 ACCEPT"；呈现顺序引导先看证据后看结论 | Human gate | ✅ |
| 6 | 反馈间隔（Feedback interval） | 及时反馈强化行为 | 每次验收后的即时确认：ACCEPT / REJECT / MODIFY 之后立刻给出该决策对后续任务与训练轨道的影响（一行即可） | Human gate 之后、Dispatch Card 呈现 | ✅ |

## 3. 落地场景

### 3.1 Dispatch Card 呈现（进度效应 + 承诺一致性）

Dispatch Card 头部先呈现**已完成链**（本任务之前的最近 N 项已验收任务，一行一项：
TASK_ID → 产物 → 验收结论），再呈现本任务声明。让用户看到自己在推进一条连续的链，
而不是孤立的单点任务。随后重申本任务与用户此前确认方向的对应关系。

```text
已完成链（近 3 项，均已验收）：
  ADT-2026-08-06-005 → protocols/CONCURRENCY_LIMIT.md       → ACCEPT
  ADT-2026-08-06-003 → ROADMAP.md § PT（后训练轨道）        → ACCEPT
  ADT-2026-08-06-006 → protocols/HOLDER_TOKEN.md            → ACCEPT
本任务：ADT-2026-08-06-008 → protocols/HUMAN_FACING_PSYCHOLOGY.md
与你此前确认方向的关系：延续 ROADMAP.md § PT 心理机制指示（你于 2026-08-06 确认 STRATEGY_ADOPTED）
```

### 3.2 Holder Summary（进度效应 + 蔡格尼克效应 + 损失厌恶）

Summary 固定三段式，顺序不可调换：

1. **已完成的**（进度效应）：已完成链 + 阶段完成度。完成度的分母必须来自预绑定计划，
   遵守 AGENTS.md § Human-facing evidence discipline 的进度反膨胀规则；
2. **未完成的**（蔡格尼克效应）：开放项/待办/被 REJECT 项显式列表，每项带"下一步"；
3. **已沉淀的**（损失厌恶）：已 merge 成果列表，标注"已进入 main，回退需新 revert 任务"。

```text
已完成：本阶段 3/5（分母来自 PT 轨道授权计划）
  ✅ ADT-...-005 / ✅ ADT-...-003 / ✅ ADT-...-006
未完成：
  ⬜ ADT-...-008 心理机制协议 — 下一步：CHECKER_AUDIT
  ⬜ PT 数据管道最小闭环 — 下一步：等待 Human 授权
已沉淀（不可回退价值）：
  🔒 P0 三件（隔离/并发/令牌）已 merge 进 main；PT 轨道已固化进 ROADMAP.md
```

### 3.3 Human gate（承诺一致性 + 选择架构）

Human gate 的呈现顺序：**验收标准重申 → 证据摘要 → 决策选项**。

- 先呈现用户此前确认的验收标准（来自 Dispatch Card 的成功标准），再呈现证据摘要——
  让 ACCEPT / REJECT / MODIFY 与承诺基线对照，而不是凭印象点选；
- 默认动作是"查看证据"，不是 ACCEPT；ACCEPT 需要显式选择，不默认勾选；
- REJECT 与 MODIFY 永远可用，且不附带任何劝阻性文案。

```text
你此前确认的验收标准：协议包含 ≥5 个心理机制、≥4 个落地场景、边界与伦理、轻量版兼容。
证据摘要：6 个机制 / 4 个场景 / 7 条伦理边界 / 轻量版兼容表 — 见 branch@HEAD diff。
决策：[ 查看证据 ]（默认）  [ ACCEPT ]  [ REJECT ]  [ MODIFY ]
```

### 3.4 收工汇报 / 跨机接力（反馈间隔 + 蔡格尼克效应）

- 每次任务收尾（Progress Receipt / 收工汇报）必须带一行**决策影响**（反馈间隔）：
  本次结果对后续任务或训练轨道意味着什么；
- 跨机接力时，交接摘要显式列出**未关闭项**清单（蔡格尼克效应）：下一个窗口/下一次会话
  从缺口开始，而不是从头开始。未关闭项清单是交接摘要的第一节。

```text
本次决策影响：协议已提交至 hermes/adt-human-facing-psych-r1，下一步 CHECKER_AUDIT；
验收后即成为 PT 轨道"心理机制落地"的第一份正式协议。
未关闭项（交接给下一个窗口）：
  1. CHECKER_AUDIT — 独立审计本协议与 AGENTS.md 引用
  2. Human ACCEPT / REJECT / MODIFY — 黄金标签决策
```

## 4. 边界与伦理

心理机制是"帮助用户看见自己的进度和承诺"，不是"诱导用户做违背意图的决定"。
以下边界在任何接触面、任何模式下强制生效：

1. **帮助看见，不是诱导决策**：机制的作用是让用户看见自己的进度、承诺与未完成项，
   帮助用户做出**符合自己意图**的决策。禁止用任何机制制造"必须 ACCEPT"的压力。
2. **用户随时可关闭**：所有心理呈现都是可选的。用户可要求"只报状态"——接触面必须
   支持纯状态模式，且关闭不影响任何治理功能、任何字段完整性。
3. **不制造虚假紧迫感**：禁止人为 deadline、倒计时、稀缺性（如"仅剩一个名额"）等
   虚假紧迫信号。"差一点完成"的进度效应只能来自真实、预绑定的计划分母，禁止捏造数字。
4. **承诺重申不是绑住用户**：承诺一致性是温和提醒，不阻止用户改变方向。用户改变方向
   永远合法；方向改变后，接触面必须立即更新承诺基线，不得继续引用旧承诺。
5. **默认动作的伦理**：选择架构的默认动作只能是"更多信息/更多反思"，不能是"同意"。
   默认呈现顺序引导先看证据后看结论。
6. **不用于操控训练数据**：心理机制服务于用户决策质量，间接改善 PT 训练数据
   （黄金标签）质量；禁止为了让标签"更干净"而引导用户做特定选择。
7. **不削弱既有边界**：本协议不改变 Human 的最终决定权、不改变证据纪律字段、
   不改变进度反膨胀规则——心理呈现不得美化或隐藏任何字段值。

## 5. 与现有协议的关系

| 现有机制 | 关系 |

| AGENTS.md § Human-facing evidence discipline | 心理机制是证据呈现的**组织方式**，不是替代：FACT、AUTHORITY、ACTION、RESULT、ARTIFACT_TYPE、ARTIFACT_LOCATION 等字段仍必须完整真实；心理呈现不得伪造或美化字段值 |
| protocols/ARTIFACT_DELIVERY.md | Delivery Card 负责"产物在哪"，心理机制负责"怎么呈现完成链"——两者叠加：产物位置仍是完成通知的核心内容，心理机制在其周围组织呈现 |
| ROADMAP.md § PT 后训练轨道 | 本协议是 PT 轨道"心理机制（Human Facing）"一节的落地设计。心理机制改变用户交互模式（机械验收 → 反思验收），进而改变训练数据形态：黄金标签从"点一下"变成"经过反思的决策" |

## 6. 与轻量 ADT 的兼容（公司机 WorkBuddy）

公司机 WorkBuddy 使用轻量版 ADT（LIGHTWEIGHT_EXECUTION_FLOW 系）。本协议机制
**大部分可直接平移**：心理机制作用于呈现层，不改变治理拓扑、证据字段或授权边界。

| 机制 | 轻量版直接可用 | 说明 |
|---|---|---|
| 进度效应 | ✅ | 一行"已完成链 + 剩余缺口"即可 |
| 承诺一致性 | ✅ | Human gate 前重申一句话承诺基线 |
| 蔡格尼克效应 | ✅ | 显式列出未关闭项清单 |
| 损失厌恶 | ✅ | 一行"已沉淀成果" |
| 选择架构 | ✅ | gate 默认动作同样必须是"查看证据" |
| 反馈间隔 | ✅ | 每次验收后一行即时确认 |

平移原则：

- 机制全部可平移；呈现篇幅可压缩（轻量版每场景 ≤ 3 行）；
- §4 边界与伦理在轻量版中同样强制，不因轻量而豁免；
- 轻量版可省略 §3 的完整三段式，但"已完成 / 未完成"的区分不得省略。

## 7. 反目标

- 不为心理机制增加新的"人类确认步骤"（与 ARTIFACT_DELIVERY 反目标一致）。
- 不把"用户没点 ACCEPT"当成系统故障来施压。
- 不制造虚假进度、虚假紧迫感、虚假稀缺。
- 不引入新的状态系统或新字段——心理机制只重组现有字段的呈现，不改动数据结构。
- 心理呈现不得隐藏或弱化任何失败、REJECT、阻塞信息——蔡格尼克效应只显式化**真实的**
  开放项。
