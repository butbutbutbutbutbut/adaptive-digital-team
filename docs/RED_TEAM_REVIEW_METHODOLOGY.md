# 三方向对抗审查方法论（Red Team Review Methodology）

**定位**：从 2026-08-09 主 base 整合三队对抗审查（Human Facing / 事实严谨 / 范式优雅）实战沉淀的可复用规程。
**约束**：方法论自身受反目标治理约束——它必须比审查对象轻，审查必须比修复便宜（见 §7）。

---

## 1. 适用域与触发时机

### 1.1 该派红队（四类场景，命中任一即派）

1. **重大结构变更**：表/库/目录级重构、数据模型变更后
2. **数据迁移**：任何跨表/跨库/跨系统搬运，尤其旧数据留存的场景
3. **面向用户的界面与流程重构**：Human 每天打开的视图、仪表盘、看板
4. **治理机制变更后**：协议/流程/文档体系改动，先审后立

派单标准一句话：**「Human 能否一眼看懂现状」与「数据是否真的完整」，若无法用一行 FACT 回答，就该派红队。**

### 1.2 不该派红队（轻量原则，原则一校准）

- 小改动不派：单文件文档修正、字段改名、纯文案调整——Maker 自查 + Checker 复核即可
- 治理成本不得超过保护价值：审查（派单 + 三队 + 修复 + 复验）总成本超过变更价值 20% 时不派
- 连续 3 次审查同一对象无新发现：降级为抽查或砍掉对应检查项
- 只读任务、A/B 模式对话不派（无变更可审）

## 2. 三方向定义

三条红队并行派单、互不通信、各自独立上下文。每个方向 = 一种立场 + 一套问题集 + 一套证据要求。

### 2.1 方向 A：Human Facing（人类感知层）

- **立场**：以最终人类用户「第一眼体验」为立场——打开界面能否不看文档就懂现状
- **核心问题集**：
  1. 读路径全链路核对：写入的新数据，仪表盘/视图读的是不是同一张表？（8/9 实战：30 组件 24 个指向旧表）
  2. 感知载体核对：迁移是否重建了视图/时间轴/看板？（母本 26 视图 vs 新表全默认 Grid）
  3. 可见性核对：旧数据是否仍可见造成双写混淆？（新旧 10 表并立、132 条旧数据可见）
  4. 枚举瘦身：状态枚举是否超过人类扫读粒度？有无零使用僵尸值？（33 枚举只用 15）
  5. 人话/机器分层：交付物、标题是否混入 SHA/PR 号/状态机常量？（53 节点 ≥20 条被污染）
  6. 诚实呈现：无更新规则的数字字段（进度 = 表演性诱饵）；决定是否事前录入而非追认账本
  7. 图表配置自检：空配置、AND 永空过滤、名不副实的表名/视图名
- **证据要求**：逐组件/逐视图/逐字段枚举（数据源 table_name、视图数量、枚举分布），给具体数字
- **输出格式**：发现清单【高/中/低】+ 位置 + 证据 + 修复建议；总结论 = Human Facing 达成度评分（0-10）+ 一句话给 Maker

### 2.2 方向 B：事实严谨（数据完整性）

- **立场**：以「应迁/实迁/缺失/重复」的可核对账目为立场，只认可验证的数字
- **核心问题集**：
  1. 记录级完整性：应迁 N、实迁 N、缺失 0——逐条对应，不留模糊
  2. 字段级完整性：源表独有字段逐字段比对（备注/下一步、完成日期、开始日期——8/9 实战丢失 3 类）
  3. 映射保真：状态/类型关键词映射是否失真（已验收→已完成 语义降级）；同实体跨套是否类型不一致
  4. 实体级去重：同名/同语义双写（11 组 20 条），尤其状态互相矛盾的双写
  5. 关联断裂：迁移后关联字段是否全空（23 条任务关联节点全空）
  6. 证据链：决定/反馈的关联证据、证据依据是否可追溯
  7. 编号追溯：双轨编号（TASK_ID vs NO.xxx）是否一致、有无悬空
  8. 存疑值：日期倒挂等存疑值不得继承，标 UNVERIFIED
- **证据要求**：核对表（应迁/实迁/缺失/重复 + 核对依据列）；每条发现给记录实例（表/字段/编号/数字）
- **输出格式**：迁移完整性核对表 + 发现清单；拿不到证据的结论标 UNVERIFIED，禁止推测

### 2.3 方向 C：范式优雅（模型与哲学一致性）

- **立场**：以母本/哲学/愿景的一致性为立场——结构是否闭合、字段是否冗余、是否轻
- **核心问题集**：
  1. 模型闭合：同表是否混装两种语义（时间线节点 vs 平移节点——37/53 断链）
  2. 引用类型：跨表引用是 link 还是 text？（母本 12 link vs 主 base 0——改名即静默断链）
  3. 事实源单一：同一实体是否双轨双写两套状态机（决定/反馈 6 组 1:1）
  4. 字段冗余：无数据字段 = 自我增殖（保密等级 4 表 0 数据）；缺字段继承（formula 照抄母本）
  5. 命名一致：枚举/名称/来源字段是否统一（来源三义混杂）
  6. 死表风险：无输入来源的表到点就砍（反馈表 = 一次性输入）
  7. 结构化不降级：里程碑/关联不得压成备注文本标签
  8. 归档≠改名：旧表是否真正冻结（132 条仍在库、仍可写）
- **证据要求**：对照母本逐表逐字段实测比对；范式标尺打分（结构/哲学/愿景三维度）
- **输出格式**：发现清单 + 范式总评（等级制，如 B-）+ 「三刀」：必须优先处理的 P0 判断

## 3. 执行规程

### 3.1 派单前：审查对象上下文包（每队必带）

- 对象：base/仓库/文件路径 + 精确范围
- 对照基准：母本/旧版/愿景文档
- 哲学约束：protocols/PHILOSOPHY.md 五原则（尤其原则一/二/五）
- 工具路径：可用的只读命令（lark-cli base +record-list/+field-list、git log 等）
- 输出要求：本方法论 §2 对应方向的格式

### 3.2 红队纪律（三条）

1. **独立上下文**：三队并行派单、互不读对方报告；不共享中间结论
2. **只读**：禁止任何写操作；证据来自实查（记录/字段/组件枚举），不是印象
3. **证据纪律**：每条发现 = 位置 + 具体证据（表名/字段/记录实例/数字/枚举分布）；拿不到证据标 UNVERIFIED，禁止推测性结论。「看起来没问题」不是结论——是没查

### 3.3 输出格式（统一骨架）

```text
发现清单：【高/中/低-N】标题
- 位置：…
- 证据：…
- 修复：…
总结论：评分或总评 + 一句话给 Maker（先修哪三件事能到几分）
```

### 3.4 三队并行派单模板

```python
delegate_task(task_id="ADT-YYYY-MM-DD-0XX", role="red-team-{a|b|c}", context={
    "object": "<审查对象精确标识>",
    "baseline": "<对照基准>",
    "direction": "human-facing | fact | paradigm",
    "philosophy": "protocols/PHILOSOPHY.md（原则一/二/五）",
    "tool_paths": ["<只读命令/技能清单>"],
    "read_only": True,
    "output": "发现清单【高/中/低】+位置+证据+修复建议；总结论（评分或总评）",
})
```

A/B/C 三个 direction 各派一队；汇总时按方向并表，发现冲突（如 A 说删旧表、B 说删前须补录）以证据更强者为准。

## 4. 修复闭环

- **P0（高）**：事实源污染/数据丢失风险/用户看到过期事实——立即修（仪表盘切新表、双轨归并）
- **P1（中）**：功能缺失/关联断裂/语义降级——随最近迭代修
- **P2（低）**：命名/噪音/死字段——积攒批量修（整合类变更正是最佳砍伐时机）
- **复验**：修复后至少三处抽查——①仪表盘/视图读的是新数据源 ②关键视图能画出（时间轴/看板）③数据抽查（抽样记录核对字段值）；修复人自验 + 独立复验
- **归档纪律**：删表/删数据前先导出本地快照（JSON/CSV）并验收「核心表已完整承载源表信息」，否则禁止删除（8/9 教训：备注/下一步 17 条、完成日期 13 条只在归档侧）

## 5. 实战案例：2026-08-09 主 base 整合审查（附录）

对象：5 新表 + 5 旧表 + 4 仪表盘整合；三队并行审查。真实发现节选（★ = 已常规化为检查项）：

- ★ A-高1：仪表盘 30 组件中 24 个指向旧表——写新读旧，仪表盘是过期事实（→§2.1-1）
- ★ A-高2：视图层零建设，5 新表全默认 Grid；母本 26 视图（→§2.1-2）
- ★ A-高4/中6：枚举 33 个只用 15；进度字段 28 条全空（→§2.1-4/6）
- ★ B：记录级 61/61 完整，但字段级丢失 3 类——备注/下一步 17 条、完成日期 13 条、开始日期 4 条（→§2.2-2）
- ★ B-高4：实体级重复 11 组 20 条，状态矛盾双写（NO.014 未开始 vs NO.052 已完成）（→§2.2-4）
- ★ C-高2：link→text 全面退化，母本 12 link vs 主 base 0（→§2.3-2）
- ★ C-高3：决定/反馈双轨 1:1 双写 6 组，两套状态机（→§2.3-3）
- 教训：迁移完整性「记录级 100%」会掩盖字段级丢失——完整性必须逐字段核，不能只数行

## 6. 评分标准（可复用维度）

**Human Facing 达成度**（0-10，每维 0-2 分）：

| 维度 | 满分标准 | 8/9 实战（修复前 → 后） |
|---|---|---|
| 读路径一致 | 仪表盘/视图读新数据源 | 0/2（24/30 旧表）→ 2/2 |
| 感知载体 | 时间轴/看板/按需视图齐全 | 0/2 → 2/2 |
| 可见性 | 无新旧双写混淆 | 0/2（10 表并立）→ 2/2 |
| 信息密度 | 枚举/字段在人之粒度 | 1/2（33 枚举）→ 2/2 |
| 诚实呈现 | 无表演性字段/追认账本 | 0/2 → 1/2（部分归位） |

修复前 3/10 → 修复三件事（仪表盘切表、照母本建视图、删旧表）后 7/10。
**事实严谨达成度**：记录级 100% + 字段级 0 丢失 + 实体级 0 重复 = 10/10（8/9 实战 ≈7/10）。
**范式优雅等级**：结构闭合 + 引用织网 + 零死字段 + 事实源单一 = A（8/9 实战 B-）。

## 7. 反目标约束（与 ADT 哲学的关系）

方法论自身受 PHILOSOPHY 五原则约束，尤其原则一：

1. **审查必须比对象轻**：单次审查（派单 + 三队 + 汇总）成本不得超过审查对象价值的 20%；超出即砍流程
2. **检查项有寿命**：连续 3 次审查没抓到问题的检查项，砍掉（原则一第 3 条扳机）
3. **只读边界**：红队只发现不修复——修复走正常 Maker 流程，不自我授权（原则三）
4. **证据纪律即原则五**：事实优先——红队结论必须指向可验证来源，UNVERIFIED 如实标注
5. **方法论不许膨胀**：本文档 200 行封顶；新检查项必须来自实战发现，禁止理论预置（原则二：写不出 FACT 证明价值的就是话术）
